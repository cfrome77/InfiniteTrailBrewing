## Project-specific notes

- **ESLint** uses flat config importing `eslint-config-next/core-web-vitals`
  directly. `FlatCompat` fails against it ("Converting circular structure to
  JSON"). The `@typescript-eslint` plugin is scoped to `**/*.ts(x)`, so rules
  for it must declare the same `files` glob.
- **Jest** must transform `@portabletext/to-html` (ESM-only). `next/jest`
  prepends its own `transformIgnorePatterns`, so `jest.config.ts` overrides the
  resolved config rather than passing it through the factory.
- **Sanity schemas** default-export schema objects by convention; the
  `import/no-anonymous-default-export` rule is disabled for `sanity/schema/`.
- **`next-env.d.ts`** churn is normalized by `scripts/stabilize-env.js`
  (`postbuild` and `dev`). `*.tsbuildinfo` is a build artifact and is ignored.
- **Admin Server Actions** authorize server-side via `lib/admin-auth.ts`
  (`requireAdmin`); the Sanity Studio UI is not the security boundary.
- **Revalidation** is HMAC-verified and fail-closed: 503 when
  `SANITY_REVALIDATE_SECRET` is unset, 401 on missing/invalid signature.
  Verification must match `@sanity/webhook`: header `sanity-webhook-signature`,
  value `t=<unix ms>,v1=<base64url>`, HMAC-SHA256 over
  `"<timestamp>.<raw body>"`. A bare hex HMAC of the body alone is *not*
  compatible and will reject every real webhook. `tests/unit/revalidate-route.test.ts`
  pins a fixture generated by `@sanity/webhook@4.0.4`; if it fails, the
  signing contract drifted. Read the raw body with `req.text()` — re-serialising
  parsed JSON breaks the signature.
- **`/admin/login` must stay `dynamic = "force-dynamic"`.** It calls
  `isAdminAuthConfigured()`, which reads `ADMIN_SESSION_SECRET`. Statically
  prerendered, that read is baked in at build time and a secret supplied only at
  runtime leaves the page showing "not configured" forever. Guarded by
  `tests/unit/admin-login-page.test.ts`.
- **`proxy.ts` matcher must include `/admin/login`**, or its "already signed in"
  redirect branch is unreachable.
- **Rate limiters are module-level state**, so they persist across tests. Keep
  each limiter in its own `lib/*-limiter.ts` module (a `"use server"` file may
  only export async functions, so it cannot be reset from a test) and call
  `.reset(key)` in `beforeEach`.
- **Public Server Actions that send email or write data need their own limiter.**
  `subscribeToNewsletter` is directly callable by anyone regardless of the UI.
- **Newsletter success wording is deliberately uniform** across new, existing and
  re-subscribed addresses so the action cannot be used to enumerate subscribers.
- **Brand assets** live in `lib/brand.ts`. Import `BRAND.logo` /
  `BRAND.wordmark`; do not paste the Blob URLs into components again.
- **Adding an import via script** — several files (`app/page.tsx`,
  `app/contact/page.tsx`, `app/our-story/page.tsx`) have multi-line `import {`
  blocks. Inserting after the last line that *starts with* `import ` lands
  inside the braces and produces a syntax error. Anchor on the closing
  `} from "..."` line instead.
- **Playwright locally** needs `npx playwright install chromium` first;
  otherwise every test fails with "download new browsers". Local runs use
  `npm run dev`, which fetches live Sanity data and can hang — prefer
  `CI=1 npm run test:e2e` to exercise the production build the way CI does.
- **`npm audit` overstates runtime risk here.** Most findings come from
  Sanity's CLI, which never ships. Check `.next/server` and `.next/static`
  for the package before treating an advisory as applicable. The suggested
  fix for `sanity` is a downgrade to v5 and would break the schemas.
